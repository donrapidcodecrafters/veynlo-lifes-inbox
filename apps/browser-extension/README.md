# Veynlo browser extension

Manifest V3 extension (Chrome/Edge/Brave — any Chromium-based browser) that
saves the current page, or a text selection, straight into the user's Veynlo
inbox via the existing `/v1/ingestion/manual` endpoint.

No build step: `public/` is loaded as-is by the browser, so there's nothing
to compile or bundle.

## Load it locally

1. Open `chrome://extensions`.
2. Enable "Developer mode" (top right).
3. Click "Load unpacked" and select `apps/browser-extension/public`.
4. Pin the Veynlo icon to the toolbar, click it, and sign in with an existing
   Veynlo account.

The extension talks to `http://localhost:4000` by default (configurable on
the options page, `chrome-extension://<id>/options/options.html`) and
authenticates with a bearer token via `x-veynlo-platform: extension` — the
same dual cookie/bearer auth transport the mobile app uses, since an
extension has no shared cookie jar with the web app's origin.

## What it does

- **Toolbar popup**: sign in/out, "Save this page" (title + URL), "Save
  selected text" (reads the current tab's text selection via
  `chrome.scripting.executeScript`).
- **Right-click menu**: "Save page to Veynlo" / "Save selection to Veynlo"
  on any page or selected text.
- **Options page**: shows the signed-in account, lets you sign out, and lets
  you point the extension at a different API base URL for local dev.

Every capture is filed through the real ingestion pipeline
(`ingestion.service.ts`'s `ingestManualText`) — same domain classification
and structured extraction as an emailed receipt or bill, just with
`kind: "manual_entry"` as the source. There is no dedicated `saved_items`
domain yet (spec §29); this is a deliberate reuse of existing, working
infrastructure rather than a half-built parallel path. Revisit if captured
pages need their own fields (e.g. a product price snapshot) that plain
subject/body text can't carry.

## Permissions

`activeTab` + `scripting` (not the broader `tabs` permission) — the popup
and context menu only ever see the tab the user just interacted with,
consistent with the "authorization before retrieval" principle applied
elsewhere in this codebase. `host_permissions` is scoped to
`localhost:4000`/`localhost:3000` for local dev; a production build needs
the real API/web origins added.

## Icons

`public/icons/icon-{16,48,128}.png` are placeholder solid brand-color
squares, generated by `scripts/generate-icons.py` (no Pillow/image library
dependency — writes minimal valid PNGs by hand). Replace with real designed
icons before any store submission; regenerate the placeholders with:

```bash
python3 apps/browser-extension/scripts/generate-icons.py
```

## Verified

Loaded via a Playwright persistent context
(`--load-extension`/`--disable-extensions-except`) against a real running
API: sign-in (token stored via `chrome.storage.local`), `/v1/auth/me`,
save-page → `/v1/ingestion/manual` (verified with a temporary `tabs`
permission, since Playwright can't simulate a genuine toolbar-icon click
that `activeTab` requires — reverted before commit), options page reflecting
session state, API-base persistence across reload, and sign-out revoking
the session server-side and propagating to the popup. Not yet verified:
the right-click context menu items (no Playwright API to drive native
browser context menus) and a packaged/signed store build.
